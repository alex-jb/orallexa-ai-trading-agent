## What to transfer from Shadow

The [Shadow repository at `70c4db3`](https://github.com/alex-jb/shadow-mentor/tree/70c4db3196418bdeec4310bdf0d71638a6d19b71) has [hash-linked, signed session events](https://github.com/alex-jb/shadow-mentor/blob/70c4db3196418bdeec4310bdf0d71638a6d19b71/packages/attest-core/session.js), [byte-hash-backed source maps](https://github.com/alex-jb/shadow-mentor/blob/70c4db3196418bdeec4310bdf0d71638a6d19b71/lib/document-source-map.js), and an [offline verifier](https://github.com/alex-jb/shadow-mentor/blob/70c4db3196418bdeec4310bdf0d71638a6d19b71/bin/verify-chain.mjs). Its [threat model](https://github.com/alex-jb/shadow-mentor/blob/70c4db3196418bdeec4310bdf0d71638a6d19b71/docs/THREAT_MODEL.md) distinguishes tamper evidence after capture from the truth of the captured data; its [coverage matrix](https://github.com/alex-jb/shadow-mentor/blob/70c4db3196418bdeec4310bdf0d71638a6d19b71/docs/AUDITOR_COVERAGE_MATRIX.md) does not assert complete authorization or human-approval coverage. A signature is not a trading-safety or performance certificate.

For the paper loop, bind a stable run and order-intent ID to the timestamp, ticker, signal, source bytes/hash and publication/as-of time, strategy/configuration commit, quote and age, risk decision, order type/quantity, broker `client_order_id`, broker acknowledgment, cumulative fills, assumed or observed fees, realized P&L, drawdown and LLM cost. Reject placeholder source hashes when source data is required; do not copy Shadow's document schema or its fixed probability labels as if they were empirically calibrated.

The first implementation target is **durable pre-submit intent** in PR #15's paper loop. A crash after broker acceptance but before the current pending-state write can leave no local order record; a later calendar day may generate a new client ID. Persist the intent before any broker submission, fail closed on a failed write, reconcile unresolved intents by their original client ID, and block new orders while the outcome is unknown. Then add an independent, read-only signed export and offline verifier. Keep signing outside the broker submission path. Verify crash and I/O failures with synthetic broker fakes; no external order is needed.

**Implementation update:** [draft PR #32](https://github.com/alex-jb/orallexa-ai-trading-agent/pull/32), stacked on #15, now checkpoints the intent and audit row before broker submission, fsyncs file and directory entries, recovers by the original client ID, and withholds a comparison until broker position verification and a later usable completed-bar run. Its 70 related local fake-broker tests passed; the complete test suite could not be collected in that local environment because optional dependencies were missing. #32 has no GitHub CI run while its base is another draft branch. This is an unmerged implementation, not observed Alpaca execution; signed exports, a freshness age limit for completed bars, and raw-source snapshots remain open work.

### Model and interface check (2026-09-30)

- [GPT-6.1 Sol](https://openai.com/index/introducing-gpt-6-1-sol/) (`gpt-6.1-sol`) and [Claude Sonnet 5.5](https://platform.claude.com/docs/en/models/sonnet-5-5/overview) (`claude-sonnet-5-5`) have API access at published standard text rates of $2/M input and $10/M output tokens. Sonnet 5.5 has migration changes affecting tool use and thinking blocks. Keep the current debate path as a baseline; a new model belongs in a **shadow comparison**, not a silent replacement. Provider benchmarks on unrelated tasks do not establish ticker selection or trading edge.
- For bounded, typed news extraction, compare one cheaper challenger—[GPT-6 Luna](https://developers.openai.com/api/docs/models/gpt-6-luna), [Gemini 3.8 Flash](https://ai.google.dev/gemini-api/docs/models/gemini-3.8-flash), or [Mistral Small 4](https://docs.mistral.ai/models/mistral-small-4-0-26-03)—against the existing Claude path and a deterministic rule baseline. Jev remains an optional fourth arm only with approved early-access credentials and independent human labels. Gemini 3.8 Flash's introductory pricing expires after 2026-12-31; record the actual bill and provider/model revision rather than carrying today's advertised price forward.
- [Claude Managed Agents permission policies](https://platform.claude.com/docs/en/managed-agents/permission-policies) are **beta** and can emit `evaluated_permission` and `evaluation` on its own agent/MCP tool events; `auto` is opt-in, the built-in agent toolset defaults to `always_allow`, and application-executed custom tools are outside that policy. The broker adapter and API server still enforce paper-only restrictions and authorization in code. The events may be copied into a read-only audit trace if this product is separately adopted.
- [Gemini 3.8 Live](https://ai.google.dev/gemini-api/docs/changelog) models are GA, while the [Live API guide](https://ai.google.dev/gemini-api/docs/live-api/capabilities) still says preview and accepts at most one video frame per second. [Agentic video understanding](https://ai.google.dev/gemini-api/docs/video-understanding) dynamically inspects transcripts/frames/audio with **Flash** models, including 3.8 Flash; it is a separate offline-video feature, not the Live video stream. Neither is needed to validate this daily-bar trading pilot.
- The attached September developer email points to [ElevenLabs' September 28 release](https://elevenlabs.io/docs/changelog/2026/9/28): `eleven_v4` is for text-to-dialogue, and `eleven_v4_turbo` streams via WebSocket, with a vendor-reported median inference latency around 100 ms. A later bilingual morning audio brief could read a finalized, source-linked paper report; the TTS component gets no signal, risk, or broker tool access. Compare pronunciation and factual parity with the underlying text before adding audio. The personal email screenshot is not included in the repository.

**Predeclared offline trial, not results:** Freeze a licensed or synthetic time-stamped corpus before calling a new provider: for example, 200 company-news items (earnings/guidance/regulatory/other and explicit company relevance), 30 financial-document claim/evidence cases, and 30 adversarial tool/permission cases. Have two people label independently and adjudicate disagreements; store evidence IDs rather than assuming another model's answer is truth. Keep future articles and same-event duplicates out of the fitting split. Fix prompts, schemas (`event_type`, `concerns_company`, `evidence_span_ids`, `abstain`), model IDs, temperatures, seeds where supported, source hashes, token budgets, retry rules and an evaluation script. Disable retrieval and broker access. Report per-class precision/recall and macro-F1, relevance Brier/calibration **only for defined numeric probability outputs**, abstention and missing-source errors, evidence citation correctness, paper-order refusal on forbidden paths, p50/p95 latency, and **observed** input/output tokens and dollars per 1,000 items with bootstrap uncertainty. Separate stratified-test estimates from a later representative deployment sample. Record provider-specific failures and data rights. A model wins a role only if it improves its predeclared task without violating the cost and safety budget; news classification scores alone cannot establish forecast skill or excess return.

Illustrative **budget estimate**, not a quote or measured expense: 200 items/model at 1,500 input and 250 output tokens, no cache, search, retries, extra reasoning or other fees; current standard published text prices imply about $0.055 (GPT-6 Luna), $0.075 (Mistral Small 4), $0.413 (Gemini 3.8 Flash), $1.10 (Sonnet 5.5), and $1.10 (GPT-6.1 Sol): **$2.74 total**. A future test should stop at a $5 provider-billed cap and log actual usage per request; Jev and audio are excluded pending access and fresh pricing. This protocol has not been run, and no credentials or orders were used.
